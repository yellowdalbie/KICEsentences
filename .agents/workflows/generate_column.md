# 기출문제 유사문항 분석 칼럼 생성 스킬

사용자가 특정 문항(예: 2027학년도 6월 모의평가 공통 15번)을 바탕으로 유사문항 추천과 칼럼 작성을 요청할 때 사용하는 스킬입니다.
이 스킬을 사용하면 모바일 가독성과 웹서비스 디자인 톤앤매너에 최적화된 형식으로 마크다운 텍스트를 즉시 생성할 수 있습니다.

## 작업 순서

### Step 1. 유사 문항 탐색 및 분석 (3단계 딥 다이빙 로직)
표면적인 단원이나 단순한 수식 유사성을 넘어서, 다음 3단계 로직을 거쳐 유사 문항을 선정합니다:

1. **표면적 조건의 해체 및 본질(뼈대) 추출**:
   - 대상 문항의 껍데기를 벗겨내고, 풀이 과정에서 결정적인 역할을 하는 '핵심 사고 과정'을 한 줄로 추출합니다. (예: 정적분의 절댓값 조건 $\rightarrow$ 피적분함수의 부호 역전 추론)
2. **기출 아카이브 개념 매칭**:
   - 추출한 본질적 뼈대와 완벽하게 일치하는 논리를 요구했던 과거 수능/평가원 기출문제를 스캔합니다. 겉포장이 달라도 논리 전개 방식이 같으면 후보군에 포함합니다.
3. **진화 패턴 분석 및 스토리텔링 선별**:
   - 가장 훌륭한 교육적 서사가 나오는 문항 3개를 최종 선정합니다.
   - **원형(Prototype)**: 가장 기본적이고 직관적인 형태로 동일한 논리를 물었던 문항
   - **확장형(Extension)**: 해당 논리를 더 복잡한 상황으로 확장했던 문항
   - **결합형(Combination)**: 해당 논리가 풀이의 마지막 결정적 단서로 쓰이는 문항
- 이 로직을 통해 선정된 문항들로 칼럼을 구성하며, "기출 공부를 열심히 하면 새로운 문제도 잘 풀 수 있다"는 메시지를 담아 논리적인 설명을 준비합니다.

### Step 2. 칼럼 원고 작성 (포맷팅 규칙 엄수)
게시글(칼럼)을 작성할 때 **반드시** 다음 규칙을 지켜서 작성해야 합니다:

1. **블록 수식 사용 (모바일 텍스트 잘림 방지)**:
   - 본문 중간에 들어가는 긴 수식은 모바일 화면 너비를 초과하여 글자를 잘리게 만듭니다.
   - 따라서 조건식 등 길이가 있는 수식은 반드시 인라인(`$ ... $`)이 아닌 **블록 수식(`$$ ... $$`)**을 사용하여 별도의 블록으로 분리합니다.

2. **볼드체 띄어쓰기 (마크다운 파서 렌더링 오류 방지)**:
   - `**` 기호로 끝나는 볼드체 텍스트 바로 뒤에 한글 조사('이', '가', '은', '는', '를' 등)나 텍스트가 붙어있으면 렌더러에서 굵은 글씨로 처리하지 못하는 고질적인 문제가 있습니다.
   - **반드시** 뒷 `**` 바로 뒤에 공백을 한 칸 띄어서 작성합니다.
   - ❌ 잘못된 예: `**핵심입니다**라고`
   - ✅ 올바른 예: `**핵심입니다** 라고`

3. **충분한 줄바꿈 (가독성 확보)**:
   - 단락과 단락 사이에는 빈 줄에 `<br>` 태그를 명시적으로 삽입하여 모바일에서도 답답하지 않도록 넉넉한 호흡을 줍니다.

4. **소제목 디자인 (이모지 지양)**:
   - 단락 번호에 촌스러운 이모지(1️⃣, 2️⃣ 등)를 절대 사용하지 않습니다.
   - HTML 태그를 활용해 폰트 크기와 하늘색 컬러를 사용하여 세련된 소제목 형태로 구성합니다.
   - ✅ 포맷 예시: `#### <span style="font-size:1.15em; color:var(--accent-cyan);">01.</span> 부호 유지와 변화의 본질: [2023학년도 9월 모의평가 공통 14번]`

5. **썸네일 이미지 삽입**:
   - 대상 문항과 각 유사 문항을 설명하는 부분 상단에 문항 썸네일 이미지를 포함합니다.
   - ✅ 포맷 예시: `![2023.9모_14](/static/thumbnails/2023.9모_14.png)`

6. **게시글 제목 스타일링**:
   - DB에 업로드할 때, 게시글의 제목(`title`)은 단순히 텍스트로 넣지 않고 아래와 같이 `span` 태그를 이용해 하늘색 볼드체로 지정합니다.
   - ✅ 예시: `<span style='color: #38bdf8; font-weight: bold;'>기출로 분석하는 2027학년도 15번</span>`

### Step 3. 초안 확인 및 사용자 승인
- 작성된 칼럼 원고(마크다운 텍스트)를 채팅창이나 아티팩트를 통해 사용자에게 먼저 보여줍니다.
- 사용자가 내용과 포맷을 확인하고 명시적으로 승인(게시 허가)할 때까지 대기합니다.
- 사용자가 수정 사항을 요구하면 이를 반영하여 다시 초안을 보여줍니다.

### Step 4. 데이터베이스 업데이트 및 배포
- 완성된 마크다운 텍스트를 `scratch/post_content.md`에 저장합니다.
- 해당 내용을 웹서비스 대상 게시판(원격 DB의 `posts` 테이블)에 UPDATE 하는 SQL을 실행합니다.
- 필요에 따라 `/deploy_remote` 또는 `/restart_server` 스킬을 활용하여 변경사항이 라이브 서버에 반영되도록 합니다.
