# 정적 오프라인 패키지 빌드 절차

인터넷이 없는 윈도우 PC에서 **폴더만 복사해** 쓰는 배포본을 만든다.
파이썬도 설치도 필요 없고, `시작하기.html` 을 두 번 누르면 실행된다.

## 왜 이런 구조인가

브라우저는 `file://` 에서 `fetch`/`XHR` 로 로컬 파일을 읽지 못한다(실측 확인).
반면 아래는 모두 동작한다.

| 기능 | file:// |
|---|---|
| `<script src>` 로 데이터 주입 | 동작 |
| `<img src>` 로컬 이미지 | 동작 |
| `localStorage` · `IndexedDB` | 동작 |
| `fetch` · `XHR` 로컬 파일 | **차단** |

그래서 데이터는 전부 `<script>` 로 싣고, 화면이 부르던 `/api/...` 는
`offline-api.js` 가 `window.fetch` 를 가로채 같은 모양의 JSON 으로 응답한다.
덕분에 `index.html` 과 `cart.js` 를 거의 손대지 않는다.

## 빌드

```bash
python3 build_static_data.py      # 문항·검색표·원문 → dist_static/data/*.js
python3 build_static_similar.py   # 유사 스텝 표 (약 10초)
python3 build_static.py           # 썸네일 변환·라이브러리 동봉·페이지 생성
```

`build_static.py` 는 CDN 스크립트를 내려받으므로 **빌드할 때만** 인터넷이 필요하다.
버전은 온라인 판과 같은 값으로 고정되어 있다(동작 차이를 만들지 않기 위해).

콘텐츠를 새로 반영할 때는 `build_db.py` → `build_vectors.py` →
`build_query_vocab.py` 를 먼저 돌린 뒤 위 세 단계를 실행한다.

## 크기

| 항목 | 크기 | 비고 |
|---|---|---|
| `data/` | 7.0 MB | 문항·해설·검색표·원문 |
| `thumbnails/` | 95 MB | WebP 무손실 (PNG 284MB → 67% 절감) |
| `lib/` + `static/` | 1.8 MB | katex · marked · DOMPurify · mathlive |
| **합계** | **약 104 MB** | 기존 파이썬 동봉판 361 MB |

## 서버 판과 결과가 같은지 확인하는 법

이식한 검색 로직이 원본과 어긋나면 안 되므로, 같은 질의를 서버와 브라우저에
넣어 대조한다. 확인된 항목은 다음과 같다.

- 개념유사도 검색: 행 순서·유사도 값까지 완전 일치 (오차 0)
- 문항번호 검색: 일반 질의·순수 숫자 질의 모두 일치
- 기출표현 검색, 유사 스텝, 개념 트리: 일치

특히 주의할 점이 둘 있다.

1. **동점 정렬**. 서버는 반올림된 유사도로 정렬하고 동점은 DB 반환 순서를
   따른다. `steps(problem_id)` 인덱스가 있으므로 그 순서는 `problem_id`
   오름차순이다. JS 도 같은 순서를 만든 뒤 안정 정렬해야 결과가 같다.
2. **문항번호 검색**은 단순 부분일치가 아니라 정규화 후 부분열 매칭이며,
   순수 숫자 질의는 마지막 번호와 정확히 비교한다.

## 빠지는 기능

게시판·로그인·오류 제보·이용 통계. 모두 인터넷이 필요한 기능으로,
기존 오프라인 모드에서도 이미 꺼져 있었다.

장바구니와 저장 세트는 서버 DB 대신 `localStorage` 에 보관한다.
브라우저 데이터를 지우면 함께 사라지므로 안내문에 명시했다.
